# 项目结构与功能说明

本文依据 `frp-simple-bash` 当前代码整理，说明源码目录、文件职责、调用关系及安装后的数据布局。当前版本封装官方 frp **0.72.0**。

项目由 Bash/PowerShell 安装入口、Python 共享管理核心、平台服务模板、测试和文档组成。frp 原生程序在安装时下载，不作为源码文件提交。

## 2. 根目录：安装、卸载和用户说明

| 文件 | 主要职责 |

| [Linux frps 安装入口](<../install-frps.sh>) | 选择服务端角色；本地完整源码下调用共用安装器，单文件远程执行时补齐仓库源码。 |

| [Windows frps 安装入口](<../install-frps.ps1>) | 指定服务端角色；需要时下载 Windows 共用安装器，再传递版本和包装器校验参数。 |
| [Windows frpc 安装入口](<../install-frpc.ps1>) | 指定客户端角色，调用 Windows 共用安装器。 |
| [Windows 共用安装器](<../install-windows.ps1>) | 检测管理员、Windows x64、Python；下载并校验原生 frp 和 WinSW；保护配置 ACL、创建 CMD 命令、注册服务及初始化配置。包含同版本重装与部分失败恢复逻辑。 |
| [Linux 卸载器](<../uninstall.sh>) | 接收 `frps`/`frpc` 参数，停止并注销对应服务、删除对应命令和原生程序；默认保留配置与日志。 |
| [Windows frps 卸载入口](<../uninstall-frps.ps1>) | 将服务端角色转交给共用卸载器。 |
| [Windows frpc 卸载入口](<../uninstall-frpc.ps1>) | 将客户端角色转交给共用卸载器。 |
| [Windows 共用卸载器](<../uninstall-windows.ps1>) | 通过 WinSW 停止并注销服务，删除对应命令和程序；默认保留数据，显式确认后允许对默认数据目录执行清理。 |

安装器不会自动修改防火墙。首期固定使用 0.72.0；当前升级菜单通过安装器重装该固定版本，跨版本下载、迁移与回滚仍需扩展。

## 3. 命令入口：bin

该目录放的是用户管理入口。系统服务应启动下载后的原生程序，不能启动交互菜单。

| 文件 | 调用关系与职责 |
|---|---|
| [Linux frps 命令](<../bin/frps>) | 定位安装根目录，调用 `python3 …/lib/manager.py frps`，透传用户参数。 |
| [Linux frpc 命令](<../bin/frpc>) | 调用共享核心的 `frpc` 角色。无参数进入客户端数字菜单。 |
| [Windows frps CMD](<../bin/frps.cmd>) | CMD/PATH 入口，设置 Python UTF-8 模式，调用同目录 PowerShell 入口。 |
| [Windows frpc CMD](<../bin/frpc.cmd>) | 客户端 CMD/PATH 入口。 |
| [Windows frps PowerShell](<../bin/frps.ps1>) | 设置编码及配置、原生程序路径；寻找 Python 3.11+，调用共享核心并传回退出码。 |
| [Windows frpc PowerShell](<../bin/frpc.ps1>) | 执行客户端角色的相同转发流程。 |

无参数调用进入数字菜单；`status`、`start`、`stop`、`restart` 等参数由核心命令分发器处理。

## 4. 共享业务核心：lib

[下载 helper](<../lib/download.sh>)提供国内镜像选择、官方回退、HTTPS 限制和固定 SHA256 校验，由 Linux 共用安装器调用，并随安装复制到安装目录。源码单文件入口保持自身可独立运行，使用同一镜像和固定管理器版本规则。

[源码构建工具](<../tools/build_release.py>)生成顶层为 `frp-simple-bash/` 的固定版本压缩包及摘要清单；输出在被 Git 忽略的 `dist/`，不包含本地测试数据和原生二进制。镜像目录、Cloudflare 与证书注意事项见[部署维护文档](<国内下载站部署与维护.md>)。

[管理核心](<../lib/manager.py>) 是当前唯一的 Python 业务文件。下表是文件内的逻辑分组，并非已经拆成多个物理模块。

| 逻辑分组 | 主要函数 | 功能 |
|---|---|---|
| 配置编解码 | `text`、`toml`、`read_toml`、`read_json`、`save_json` | 生成受支持的 TOML 结构，读取 TOML/JSON，转义字符串。Python 3.11+ 使用 tomllib，旧版 Linux 可使用 tomli。 |
| 保存与并发控制 | `atomic`、`lock`、`transaction`、`managed_paths` | 临时文件与原子替换、独占操作锁、多文件异常回滚。断电或强制终止场景不等同于普通异常回滚。 |
| 初始化与日志 | `initialize`、`rotate_logs`、`audit`、`show_logs` | 创建数据目录、执行日志清理、记录不含凭据的审计事件、查看日志。日志清理目前由管理器运行触发。 |
| 输入校验 | `port`、`address`、`name`、`unique_name`、`validate_profile`、`validate_mapping` | 校验端口、IPv4/IPv6/域名、名称字符、名称唯一性和映射字段。 |
| Profile 数据 | `pdir`、`load_profile`、`profiles`、`create_profile`、`rebuild_index`、`active` | 用不可变随机 ID 管理独立目录；维护别名、连接参数、索引及当前 profile。 |
| Profile 交互 | `profile_wizard`、`select_profile`、`edit_profile`、`switch` | 新建引导、编号选择、改名/编辑/删除和服务端切换。运行中切换需要确认并重建连接，停止状态只切换配置。 |
| 映射管理 | `mappings`、`mapping_wizard`、`mapping_menu`、`save_mappings` | 只操作当前 profile 的 TCP/UDP/HTTP/HTTPS 映射，支持增删改查与启停。 |
| 原生运行配置 | `render`、`verify`、`apply`、`mark_hash` | 从当前 profile 生成 frpc TOML；调用原生 `verify` 后保存；记录用于外部变更检测的哈希。停用代理不进入运行配置。 |
| 平台服务管理 | `service`、`running`、`autostart` | 适配 systemd、OpenRC 和 Windows WinSW，执行启停、重启、状态和自启动设置。 |
| 网络与连接状态 | `api`、`connection`、`wait_connection` | 使用 HTTP Basic Auth 访问管理接口；解析 Dashboard v2 的 `code/msg/data` 包装；结合代理状态、服务端 API 或当前启动日志检测连接，最多等待 30 秒。 |
| 服务端业务 | `configure_server`、`server_clients` | 配置 frps、token、Dashboard、HTTP/HTTPS vhost 端口，分页查询在线客户端和代理。 |
| 手工配置同步 | `import_external` | 检测运行配置变更，导入支持的基础字段；高级字段、includes、Store 等无法无损导入时拒绝并保留原文件。 |
| 命令与菜单 | `ask`、`confirm`、`choose`、`main_menu`、`run` | 数字输入、重试、二次确认、主/子菜单、非交互命令路由。 |
| 卸载与升级入口 | `uninstall`、`upgrade` | 经确认调用平台脚本。当前升级是固定版本重装。 |

### Profile 与映射的隔离关系

```text
服务端列表编号
    ↓ 选择得到不可变 profile ID
当前 active_profile_id
    ↓
profiles/<ID>/profile.toml + secrets.toml + mappings.toml
    ↓ 校验、生成
frpc.toml
    ↓ 原生 verify
单个 frpc 系统服务
```

修改服务端别名只改变显示名称。端口映射操作由主菜单第 9 项进入专用子菜单，每次操作绑定当前 profile ID。跨 profile 写入应被拒绝。

```bash
python3 -m unittest discover -s tests -v
```

```bash
FRP_NATIVE_DIR=/absolute/path/to/frp_0.72.0_linux_amd64 \
  python3 -m unittest discover -s tests -v
```

真机测试会操作系统服务，只适用于明确授权且满足预检的环境；不能作为普通用户的安装命令使用。

## 7. 自动检查：.github/workflows

[验证工作流](<../.github/workflows/validation.yml>)在 push 和 pull request 时触发，矩阵包含 Ubuntu、Windows：

1. 安装 Python 3.11。
2. 执行测试发现和 Python 编译检查。
3. Ubuntu 检查 Bash 脚本语法。
4. Windows 使用 PowerShell AST 解析脚本。

默认 CI 没有下载原生 frp，因此原生测试会跳过；PowerShell 语法解析通过也不等于 Windows 服务已完成实机安装验收。

## 9. 安装后的目录与数据职责

### Linux

```text
/usr/local/bin/frps -> /opt/frp-simple-bash/bin/frps
/usr/local/bin/frpc -> /opt/frp-simple-bash/bin/frpc

/opt/frp-simple-bash/
├── bin/                  # 管理命令入口
├── lib/manager.py        # 共享核心
├── native/frps           # 下载的原生服务端
├── native/frpc           # 下载的原生客户端
├── templates/            # 服务模板
└── 安装、卸载脚本

/etc/frp/
├── state.json            # 当前 profile、待生效状态、配置哈希等
├── index.json            # 从 profile 重建的索引
├── frps.toml             # 服务端运行配置
├── .canonical-frps.toml  # 最近接受的服务端配置副本
├── frpc.toml             # 当前 profile 生成的运行配置
├── profiles/<ID>/
│   ├── profile.toml      # 别名、地址、端口、TLS 开关等
│   ├── secrets.toml      # token、管理密码、证书路径等
│   └── mappings.toml     # 仅此服务端的映射
├── backups/              # 普通配置修改备份
├── logs/                 # 管理审计及原生进程日志
└── .operation.lock/      # 操作期间的独占锁目录
```

systemd 服务文件安装到 `/etc/systemd/system/`；OpenRC 安装到 `/etc/init.d/`。原生程序按已安装组件存在，不保证两个角色同时安装。

### Windows

```text
%ProgramFiles%\frp-simple-bash\
├── bin\                  # CMD 与 PowerShell 管理入口
├── lib\manager.py
├── native\               # 原生 frps.exe/frpc.exe
├── services\             # WinSW 可执行文件与动态生成的 XML
└── 安装、卸载脚本

%ProgramData%\frp-simple-bash\
└── 配置、profiles、状态、备份、日志
```

配置和运行数据不应提交到 GitHub。默认卸载保留配置与日志；profile 删除则同时移除该 profile 的映射，不额外创建删除备份。

## 10. 主要调用路径

### Linux 安装和运行

```text
install-frps.sh / install-frpc.sh
    ↓
install-common.sh
    ├── 系统/依赖/权限检测
    ├── 固定版下载或本地包 + SHA256
    ├── 安装 native、bin、lib 和服务模板
    └── manager.py <角色> configure → 原生 verify → 启动服务

用户输入 frpc
    ↓
/usr/local/bin/frpc → bin/frpc
    ↓
manager.py frpc → 主菜单 → 输入数字 → 对应业务函数

systemd/OpenRC
    ↓
native/frpc -c /etc/frp/frpc.toml
```

### Windows 安装和运行

```text
install-frps.ps1 / install-frpc.ps1
    ↓
install-windows.ps1
    ├── frp 和 WinSW 校验
    ├── 配置 ACL、PATH、服务 XML
    └── 初始配置、原生 verify、启动服务

用户输入 frpc → frpc.cmd → frpc.ps1 → manager.py frpc
Windows SCM → WinSW → native/frpc.exe -c <运行配置>
```
