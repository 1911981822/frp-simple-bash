## 一、必须依据的文档契约（原文要点）

### A. 需求文档（`frp二次封装需求文档.md`）
- §6.2 通用菜单规范：`0` 返回/退出、`q` 取消、危险操作需 `YES`、结果 `[成功]/[提示]/[失败]`。
- §7.1 frps 主菜单至少 9 项：运行状态(PID/启动时间/最近退出原因)、版本信息(当前/来源/可用更新)、路径信息(二进制/配置/服务文件/日志/备份)、服务控制、客户端连接信息、配置查看修改、日志查看(最近/持续跟踪/错误摘要)、卸载(保留配置或彻底清理)、升级(备份/下载/校验/替换重启/失败恢复)。
- §7.2 Dashboard/API 不可用时**必须明确提示真实原因，不得把过期缓存伪装成实时状态**；日志回退只作辅助诊断。
- §7.3 token 默认启用并强制最小长度；管理端口与业务端口分离；危险端口/端口占用/监听 0.0.0.0 给出警告；配置最小权限。
- §8.1 frpc 主菜单 16 项（状态/连接状态/版本路径/启停重启/自启/新建 profile/查看全部/切换/修改/删除/端口映射子菜单/日志诊断/更新卸载备份）。**第 14 项必须显示当前服务端别名**；映射增删改不得平级放主菜单。
- §8.2 profile：唯一 ID、唯一显示名称、地址、bind 端口、Dashboard 端口、认证、TLS、**创建时间、更新时间、启用状态**；名称唯一；修改名称不改连接配置与映射；切换运行中 profile 必须提示→停→切→启→等待连接检测最多 30 秒并明确显示结果；未运行只切 active；删除 profile 同时删除其映射。
- §8.3 映射子菜单固定 5 项 + 0 返回；**只加载当前 active profile 的映射**；子菜单标题/状态区显示当前服务端别名；支持 TCP/UDP/HTTP/HTTPS；映射字段含**备注（可选）**；变更流程 8 步（确认 active→进子菜单→只加载本 profile→选操作→校验→生成独立 TOML→frpc 校验→备份原子写入→运行中提示重启）。
- §10.3 状态判断**不能只靠 PID**，应综合：服务管理器状态、进程存在、配置可解析、实际连接状态、最近退出码与最近错误日志。
- §11 必须覆盖 12 类错误并给出「错误原因+影响+建议+日志路径」，不能只显示退出码。
- §12 安全 10 条：默认 token 引导、TLS/Dashboard/公网监听风险提示、密码隐藏与脱敏、配置最小权限、HTTPS+完整性+版本来源校验、不覆盖已有配置除非确认、卸载默认保留、不泄露敏感信息到日志/错误/JSON、**防命令注入**、映射开放公网前风险提示。
- §13.1 常用操作 ≤3 层菜单；菜单可中断返回，不因输错一个字段退出；重要变更可备份可回滚。
- §13.2 可维护性：模块化、版本判断不散落、Shell/PowerShell 共享配置模型与命令语义。
- §13.3 可观测性：审计安装/升级/配置修改/启停/切换 profile；日志轮转；status/--json 适合脚本采集。
- §14 CLI：`frps status/start/stop/restart/version/path/logs/uninstall/upgrade`；`frpc ... + profile list/add/use/edit/delete + mapping list/add/edit/enable/disable/delete`；`--json` 稳定兼容承诺。
- §15 验收：重复安装不无提示覆盖；Dashboard/API 不可用提示真实原因；每个 profile 映射互不污染；token/密码/TLS 私钥不明文展示或写入普通日志；配置输入错误不破坏现有有效配置；升级失败能恢复或给出人工步骤；卸载保留配置模式重装可恢复原 profile 和映射。

- §10.5 诊断输出 8 行样例（当前服务端/服务状态/进程状态/配置状态/网络检测/认证状态/最近错误/建议/日志路径）。

- §14 安装/升级/卸载详细流程；§14.3 重复安装；§14.4 升级；§14.5 卸载。
- §15.1 **错误码 E001–E017**（见文档表格）；§15.2 异常恢复原则 6 条：异常不能直接退出数字菜单、配置写入失败不得破坏旧配置、启动失败不无限重启、切换连接失败首期建议保留目标 profile 并显示失败、删除失败不删 index 记录直到全部成功、API 失败不影响本地启停。

## 二、已知「有意设计」，不要误报
- 自带 `_mini_toml` 兼容 Python 3.6、零第三方依赖。
- 镜像失败 fallback GitHub main；SHA256 清单同源（非独立签名）。
- 拒绝自定义安装目录；`--version` 只收 0.72.0。
- frp 二进制版本固定 0.72.0，与管理脚本版本分离（MANAGER_RELEASE_VERSION）。
- 升级只覆盖 manager 脚本，不动 frp 二进制与 /etc/frp 配置。
- 首期不实现（详细设计 §1.3 原文）：Web 管理面板、同时运行多个 frpc 实例、自动修改防火墙、STCP/SUDP/XTCP 完整配置菜单、HTTP/HTTPS 高级字段菜单、自动云安全组配置、集群/高可用/负载均衡。
- 【勘误】「后台兼容模式」**不在**首期不实现清单内：需求 §10.1、概要 §9.3、详细 §9.5 均明确要求「无 systemd/OpenRC 时提供后台进程兼容模式 + 明确提示自启动受限」；专用低权限服务用户按详细 §9.2:1055 已确认方案用 root/管理员，不报。
- 【勘误】映射 `note` 备注属详细 §5.4 基础字段表（可选），只是「高级字段菜单不首期暴露」，数据模型应支持。

## 三、输出格式（每个子 agent 严格遵守）
开头「审查小结」：审了哪些文件、依据文档哪些条款、按级别统计。
逐条：
```
### [角色前缀]-001 [P0/P1/P2/P3] 简短标题
- 文档依据：文档名 §条款 + 原文要点（必须引用具体条款）
- 代码位置：文件:行号（多处全列）
- 类型：功能不完整 / 边界不清 / 闭环缺失 / 逻辑bug / 规范 / 测试缺口 / 安全隐患
- 现状：代码实际做了什么（引用关键片段）
- 差距：与文档契约的偏差
- 影响：用户可见后果
- 建议：修复方向（不实施）
- 置信度：高/中/低（低置信度需说明不确定原因）
```
按 P0→P3 排序，同级按文档条款顺序。
结尾：「符合项」（明确核查过且符合文档的条款，避免主 agent 重复核查）与「需主 agent 复核」的疑点。
**每条必须能定位到具体行 + 具体文档条款，禁止臆测；不确定的标注低置信度。**
