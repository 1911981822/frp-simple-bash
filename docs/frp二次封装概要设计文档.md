## 1. 设计目标

本系统在官方 frps/frpc 二进制之上提供跨平台管理封装，目标是让用户通过简单的安装命令和数字菜单完成：

1. frps/frpc 安装、升级、卸载；
2. 后台运行、启动、停止、重启和开机自启动；
3. 首次配置向导；
4. frps 服务端连接配置管理；
5. 一个 frpc 客户端保存多个 frps 服务端 profile；
6. 通过服务端编号切换 profile；
7. 每个 frps profile 独立管理端口映射；
8. 通过 Dashboard/API 查看客户端连接信息；
9. 配置校验、备份、恢复和敏感信息保护。

本设计重点确定系统结构、模块边界、数据隔离边界和跨平台适配方式，不展开到每个函数的详细实现。

## 2. 设计原则

### 2.1 数字菜单优先

用户在终端输入 `frps` 或 `frpc` 后，默认进入交互式数字菜单。用户通过输入菜单编号执行操作，不要求记忆复杂命令。

非交互 CLI 和 JSON 输出作为自动化补充，不改变数字菜单作为主要使用方式的定位。

### 2.2 配置与运行分离

配置数据、生成的运行配置、服务进程和展示状态分别管理：

- profile 数据保存用户意图和服务端信息；
- 映射数据保存每个服务端的独立映射；
- active profile 生成当前 frpc 运行配置；
- 服务管理模块负责进程生命周期；
- 状态检测模块负责判断真实运行和连接状态。

### 2.3 profile 强隔离

每个 frps profile 都拥有独立的连接配置和端口映射集合。当前 active profile 是唯一允许生成运行配置和执行映射修改的 profile。

任何映射操作都必须先进入：

```text
修改当前 frps（服务端别名）端口映射
```

然后在子菜单中执行新增、查看、修改、启用/停用和删除操作。

### 2.4 平台能力适配

Shell 和 PowerShell 共享产品规则、配置模型和菜单语义，但分别适配操作系统的路径、权限、服务管理器和日志机制。

### 2.5 安全默认

默认启用 token 引导、敏感信息脱敏、配置权限保护、端口校验、下载校验和危险操作二次确认。

## 3. 系统范围与边界

### 3.1 系统包含

```text
安装脚本
├── Linux Bash 安装器
├── Windows PowerShell 安装器
├── 系统与架构检测
├── frp 下载、校验和版本管理
└── 服务注册与初始化

管理 CLI
├── frps 数字菜单
├── frpc 数字菜单
├── 非交互命令
└── 可选 JSON 输出

管理核心
├── 配置读写
├── profile 管理
├── 映射管理
├── 服务生命周期管理
├── 状态和连接检测
├── Dashboard/API 适配
├── 日志管理
└── 备份与恢复
```

### 3.2 系统不包含

首期不包含：

- Web 管理后台；
- 同一台设备同时运行多个 frpc 实例；
- frps 集群、高可用和负载均衡；
- 自动修改云厂商安全组；
- 自动申请域名和证书；
- STCP、SUDP、XTCP 等高级代理类型的完整菜单管理。

## 4. 总体架构

### 4.1 逻辑架构

```text
┌──────────────────────────────────────────────┐
│                 用户终端                     │
│       frps / frpc / 安装脚本 / 参数命令       │
└──────────────────────┬───────────────────────┘
                       │
┌──────────────────────▼───────────────────────┐
│                交互与命令层                   │
│  数字菜单 │ 输入校验 │ 子菜单路由 │ JSON 输出  │
└──────────────────────┬───────────────────────┘
                       │
┌──────────────────────▼───────────────────────┐
│                管理业务层                     │
│ frps 管理 │ frpc 管理 │ Profile │ 映射管理     │
│ 首次向导  │ 状态检测 │ 连接切换 │ 升级卸载     │
└──────────────┬───────────────┬────────────────┘
               │               │
┌──────────────▼──────┐ ┌──────▼────────────────┐
│   配置与安全层       │ │   平台适配层          │
│ TOML 生成/校验       │ │ systemd / OpenRC     │
│ 原子写入/备份        │ │ Windows Service      │
│ 权限/敏感信息        │ │ 路径/进程/日志       │
└──────────────┬──────┘ └──────┬────────────────┘
               │               │
┌──────────────▼───────────────▼────────────────┐
│                 系统与 frp                    │
│     frps/frpc 二进制 │ Dashboard/API │ 日志     │
└───────────────────────────────────────────────┘
```

### 4.2 进程模型

首期采用单实例模型：

- 服务端设备运行一个 frps 实例；
- 客户端设备运行一个 frpc 实例；
- 客户端可保存多个 frps profile；
- 同一时刻只有一个 active profile；
- 切换 profile 时更新 active 配置并重启同一个 frpc 实例。

## 5. 组件划分

### 5.1 命令入口组件

负责：

- 识别 `frps`、`frpc` 调用；
- 判断是否首次安装或首次配置；
- 解析非交互命令；
- 启动对应主菜单；
- 统一处理退出码和异常。

建议逻辑入口：

```text
frps -> frps 管理入口
frpc -> frpc 管理入口
frps status/start/... -> 非交互命令执行器
frpc profile/mapping/... -> 非交互命令执行器
```

### 5.2 数字菜单组件

负责：

- 菜单标题和当前状态展示；
- 数字编号渲染；
- 输入读取和范围校验；
- 无效输入重试；
- 主菜单、子菜单和返回逻辑；
- 高风险操作确认；
- 操作完成后返回原菜单。

菜单组件不直接操作配置文件或系统服务，所有动作通过业务服务层执行。

### 5.3 安装器组件

负责：

- 检测系统、版本和架构；
- 检测管理员/root 权限；
- 选择下载版本和下载地址；
- 下载并校验官方 frp 二进制；
- 创建目录和服务用户；
- 安装管理命令；
- 调用首次配置向导；
- 注册并启动系统服务。

### 5.4 版本与下载组件

负责：

- 获取最新稳定版本或指定版本；
- 根据 OS 和 CPU 架构选择 Release 文件；
- 使用 HTTPS 下载；
- 校验 SHA256 或等价完整性信息；
- 保存版本元数据；
- 为升级提供旧版本保留和回滚信息。

默认下载源为 GitHub Releases，下载地址和镜像地址应配置化。

### 5.5 frps 管理组件

负责：

- frps 配置向导；
- frps 运行状态；
- 版本和路径信息；
- 启动、停止、重启；
- 开机自启动；
- Dashboard/API 配置；
- 客户端连接信息查询；
- 服务端配置修改；
- 升级、卸载和日志查看。

### 5.6 frpc 管理组件

负责：

- frpc 首次连接向导；
- 当前 active profile 展示；
- profile 新建、列表、编号选择、切换、修改和删除；
- 当前服务端连接状态；
- frpc 启停、自启动和日志诊断；
- 调用映射管理组件生成运行配置。

### 5.7 Profile 管理组件

负责：

- profile 唯一编号和唯一名称；
- 服务端地址、业务端口和管理端口；
- token、TLS 等连接配置；
- active profile 状态；
- profile 切换和删除；
- profile 列表展示。

服务端名称规则：

- 支持中文、字母、数字；
- 支持 `-`、`_`；
- 不允许空格；
- 其他特殊字符默认不允许；
- 名称必须唯一；
- 允许修改名称。

### 5.8 映射管理组件

负责当前 active profile 的：

- 新增映射；
- 查看映射；
- 修改映射；
- 启用/停用映射；
- 删除映射；
- 映射字段校验；
- 生成当前 frpc TOML 配置。

组件必须拒绝传入非 active profile 的映射操作请求。

### 5.9 配置管理组件

负责：

- 配置模型读写；
- TOML 生成；
- 配置语法校验；
- 原子替换；
- 备份和恢复；
- 配置权限设置；
- 敏感字段脱敏。

### 5.10 平台适配组件

统一抽象以下能力：

```text
ServiceAdapter
├── SystemdAdapter
├── OpenRCAdapter
└── WindowsServiceAdapter

PlatformAdapter
├── LinuxAdapter
└── WindowsAdapter
```

统一能力包括：

- 服务安装；
- 服务删除；
- 启动、停止、重启；
- 状态查询；
- 开机启动设置；
- 日志查询；
- 路径和权限处理。

### 5.11 Dashboard/API 组件

负责：

- 保存 Dashboard/API 地址和端口；
- 保存独立的管理用户名和密码；
- 获取在线客户端；
- 获取客户端连接时间和状态；
- 获取代理数量和代理状态；
- 处理 API 不可用和认证失败；
- 对敏感数据脱敏。

具体接口路径和字段必须在详细设计阶段结合最终 frp 版本验证，不能假定所有版本接口完全一致。

## 6. 核心业务流程

### 6.1 frps 安装流程

```text
检测系统/架构/权限
        ↓
选择版本和下载源
        ↓
下载并校验二进制
        ↓
创建安装、配置、日志目录
        ↓
输入 frps 基础配置
        ↓
输入 token/TLS 配置
        ↓
输入 Dashboard/API 配置
        ↓
生成配置并校验
        ↓
注册系统服务
        ↓
设置是否开机启动
        ↓
启动 frps
        ↓
执行状态检查
        ↓
展示安装结果
```

### 6.2 frpc 首次安装流程

```text
检测系统/架构/权限
        ↓
安装 frpc 二进制和管理命令
        ↓
创建首个 frps profile
        ↓
输入服务端名称
        ↓
输入服务端地址和业务端口
        ↓
输入 token/TLS/可选认证配置
        ↓
输入 Dashboard/API 管理端口（默认 7500）
        ↓
保存 profile
        ↓
设置为 active profile
        ↓
询问是否立即启动
        ↓
等待连接结果
        ↓
展示连接成功或失败原因
```

首次创建 profile 时先完成连接配置，不在同一向导中强制创建端口映射。映射通过后续菜单单独设置。

### 6.3 frpc 主菜单流程

```text
输入 frpc
   ↓
显示当前状态、active profile 和连接状态
   ↓
用户输入数字
   ↓
执行对应操作
   ↓
显示结果
   ↓
返回当前菜单
```

主菜单前 8 项保持固定：

```text
1. 查看当前状态
2. 启动 frpc
3. 停止 frpc
4. 重启 frpc
5. 新建 frps 服务端
6. 查看服务端列表
7. 切换当前 frps 服务端
8. 修改当前 frps 配置
```

第 9 项为：

```text
修改当前 frps（服务端别名）端口映射
```

后续为日志、开机自启动、卸载等功能。

### 6.4 profile 切换流程

```text
进入服务端列表
        ↓
显示编号、名称、地址、端口、连接状态、映射数量
        ↓
用户输入服务端编号
        ↓
校验编号
        ↓
如果 frpc 运行中：提示并二次确认
        ↓
停止旧 frpc 连接
        ↓
切换 active profile
        ↓
生成新 profile 的 frpc 配置
        ↓
启动 frpc
        ↓
最多等待 30 秒检测连接
        ↓
显示连接成功或失败原因
        ↓
返回服务端列表或主菜单
```

如果 frpc 未运行，切换只更新 active profile，不自动启动服务。

### 6.5 端口映射管理流程

```text
frpc 主菜单
   ↓
选择“修改当前 frps（服务端别名）端口映射”
   ↓
显示当前 active profile 名称
   ↓
进入端口映射子菜单
   ├── 1. 新增端口映射
   ├── 2. 查看当前服务端映射
   ├── 3. 修改端口映射
   ├── 4. 启用/停用端口映射
   └── 5. 删除端口映射
```

所有操作只能针对当前 active profile。切换 profile 后重新加载目标 profile 的映射，不允许混合展示。

### 6.6 删除 profile 流程

```text
选择服务端编号
        ↓
显示名称、地址、映射数量
        ↓
提示删除将同时删除该服务端的所有映射
        ↓
要求用户二次确认
        ↓
停止相关连接（如适用）
        ↓
删除 profile 和映射配置
        ↓
重新选择 active profile 或提示创建 profile
```

删除流程不额外自动生成备份，具体是否保留历史备份由普通配置修改和升级策略单独处理。

## 8. 数据与配置设计

### 8.1 配置目录

Linux 默认目录：

```text
/usr/local/bin/frps
/usr/local/bin/frpc
/etc/frp-manager/
├── frps.toml
├── frpc.toml
├── profiles/
│   ├── <profile-id>/
│   │   ├── profile.toml
│   │   ├── mappings.toml
│   │   └── secrets.toml
│   └── ...
├── state.json
├── backups/
└── logs/
```

Windows 默认目录：

```text
C:\Program Files\frp-manager\
C:\ProgramData\frp-manager\
├── frps.toml 或 frpc.toml
├── profiles\\<profile-id>\\
│   ├── profile.toml
│   ├── mappings.toml
│   └── secrets.toml
├── state.json
├── backups\\
└── logs\\
```

profile 使用独立目录是实现映射隔离的主要结构基础。

### 8.2 Profile 数据模型

```text
Profile
├── id                    唯一内部 ID
├── name                  唯一显示名称
├── address               IPv4/IPv6/域名
├── bind_port             frps 业务连接端口
├── dashboard_port        Dashboard/API 管理端口，默认 7500
├── auth                  token/TLS/可选认证配置
├── status                连接或运行状态
├── created_at
├── updated_at
└── mappings[]            仅属于当前 profile 的映射集合
```

名称展示格式：

```text
<名称>（<地址>:<bind_port>）
```

IPv6 展示时应使用适合地址和端口组合的格式，例如方括号包裹 IPv6 地址。

### 8.3 映射数据模型

```text
Mapping
├── name                  profile 内唯一名称
├── type                  tcp/udp/http/https
├── local_ip
├── local_port
├── remote_port
├── domain                HTTP/HTTPS 可选
├── enabled
├── note
└── advanced              预留高级字段
```

首期支持 TCP、UDP、HTTP、HTTPS。每个 profile 的映射名称只需在该 profile 内唯一，不要求跨 profile 全局唯一。

### 8.4 active profile

`state.json` 或等价状态文件保存：

```text
active_profile_id
last_selected_profile_id
last_operation
last_connection_result
```

active profile 不应直接由用户编辑，应通过菜单或 CLI 操作更新。

### 8.5 运行配置

- `frpc.toml` 仅表示当前 active profile 的运行配置；
- profile 原始配置和映射数据不直接混合写入；
- 切换 active profile 时重新生成 `frpc.toml`；
- 生成后执行语法校验；
- 校验成功后原子替换；
- 运行中的 frpc 配置变更需要提示重启。

### 8.6 敏感信息

token、管理密码、TLS 私钥等信息：

- 输入时隐藏回显；
- 菜单展示时脱敏；
- 日志中禁止输出；
- 导出时默认脱敏或剔除；
- Linux 使用文件权限保护；
- Windows 使用 ACL 保护。

---

## 9. 跨平台设计

### 9.1 Linux systemd

systemd 作为主流 Linux 首选服务管理器：

- 生成独立 service unit；
- 支持启动、停止、重启、状态和 enable/disable；
- 支持专用低权限服务用户；
- 日志优先通过 journald 管理；
- 提供文件日志路径作为辅助诊断入口。

### 9.2 Linux OpenRC

Alpine 等系统使用 OpenRC：

- 生成 OpenRC 服务脚本；
- 支持 start/stop/restart/status；
- 支持 rc-update 开机启动；
- 使用系统日志或配置目录下文件日志。

### 9.3 无服务管理器环境

提供后台进程兼容模式，但必须明确提示：

- 只能保证后台运行；
- 无法保证标准化的开机自启动；
- 用户需要自行配置兼容的启动方式。

### 9.4 Windows Service

Windows 使用 PowerShell 注册 Windows Service：

- 检测管理员权限；
- 无权限时提示以管理员身份重新运行；
- 支持自动、手动和禁用启动类型；
- 支持服务状态查询和停止；
- 服务失败时输出事件日志和文件日志路径。

### 9.5 路径和权限

平台适配层统一返回：

```text
binary_path
config_path
service_path/service_name
state_path
backup_path
log_path
```

菜单通过统一数据结构展示路径，避免将平台路径判断散落在业务代码中。

## 10. 状态与连接检测

### 10.1 frps 状态

frps 状态由以下信息综合判断：

- systemd/OpenRC/Windows Service 状态；
- 进程是否存在；
- 配置是否可解析；
- 监听端口是否正常；
- 最近退出码；
- 最近错误日志。

状态值建议：

```text
未安装、已停止、启动中、运行中、异常、未知
```

### 10.2 frpc 状态

frpc 状态除服务进程状态外，还需要检测当前 active profile 的连接状态：

```text
未安装、已停止、启动中、连接中、已连接、认证失败、地址不可达、配置错误、异常
```

### 10.3 profile 切换连接检测

切换后最多等待 30 秒，建议采用间隔轮询：

1. 检查 frpc 进程是否持续运行；
2. 检查服务端连接日志或可用连接状态；
3. 如可用，通过管理接口确认客户端上线；
4. 连接成功立即返回；
5. 超时则停止轮询并展示失败原因。

## 11. 服务端连接信息设计

### 11.1 数据来源

优先使用 frps Dashboard/API 获取：

- 在线客户端；
- 客户端名称或 ID；
- 连接时间；
- 心跳状态；
- 流量信息；
- 代理数量；
- 代理状态。

### 11.2 管理端口

- 新建 profile 时由用户手动输入 Dashboard/API 管理端口；
- 直接回车使用默认端口 `7500`；
- 管理端口与 frps 业务连接端口分开；
- 管理端口进行格式、占用和监听地址校验；
- 默认不建议无保护暴露到公网。

### 11.3 API 失败处理

- API 不可用时显示明确错误；
- 不把旧缓存伪装为实时数据；
- 可以提供日志辅助诊断；
- API 凭据和 frpc token 分开保存和管理。

具体 API 路径和数据字段在详细设计阶段根据最终 frp 版本验证。

## 12. 配置变更与一致性

### 12.1 原子写入

配置修改统一采用：

```text
读取旧配置
   ↓
创建临时文件
   ↓
写入新配置
   ↓
语法与业务校验
   ↓
保存备份
   ↓
原子替换正式文件
   ↓
按需重启服务
```

任何校验失败不得覆盖最后一次有效配置。

### 12.2 并发控制

首期建议使用操作锁避免多个终端同时修改配置：

- Linux 使用锁文件或系统锁；
- Windows 使用互斥锁或锁文件；
- 检测到已有操作时提示用户稍后重试。

### 12.3 重启策略

以下操作需要提示是否立即重启：

- profile 切换；
- token 修改；
- TLS 修改；
- 服务端地址或端口修改；
- 映射新增、修改、启用/停用和删除。

如果用户选择稍后重启，配置可以保存，但状态区必须显示“配置已修改，等待重启生效”。

## 13. 安全设计

### 13.1 安装安全

- 下载使用 HTTPS；
- 校验 Release 文件完整性；
- 显示版本、系统、架构和下载来源；
- 不覆盖已有配置，除非用户确认；
- 安装脚本避免直接执行未经查看的远程内容，提供本地下载执行方式。

### 13.2 输入安全

- 所有数字菜单输入进行范围校验；
- 端口限制为合法范围；
- 名称按允许字符集校验；
- 禁止将用户输入直接拼接到 Shell 命令、服务文件或配置文件；
- 地址、路径、文件名进行平台适配和转义。

### 13.3 操作安全

以下操作必须二次确认：

- 停止正在运行的服务；
- 删除映射；
- 删除 profile；
- 删除 profile 下全部映射；
- 卸载；
- 开放公网监听；
- 切换运行中的 profile；
- 修改认证或 TLS 配置。

### 13.4 权限安全

- Linux 配置目录按最小权限设置；
- Windows 使用受限 ACL；
- 服务尽量使用低权限用户运行；
- 管理接口默认不暴露公网；
- 日志禁止泄露 token、密码和私钥。

## 16. 部署与升级概要

### 16.1 安装目录

安装目录可由用户指定，默认路径应稳定，并通过菜单的“路径信息”展示。

### 16.2 升级流程

```text
检查当前版本
   ↓
备份当前配置和元数据
   ↓
下载目标版本
   ↓
校验文件
   ↓
停止服务
   ↓
替换二进制
   ↓
启动服务
   ↓
执行健康检查
   ↓
成功则完成

```

### 16.3 卸载流程

默认卸载：

- 停止服务；
- 删除服务注册；
- 删除管理命令和 frp 二进制；
- 保留配置和日志，除非用户选择彻底清理。

删除 profile 属于配置管理操作，按 profile 删除规则同时删除其端口映射，不要求额外自动生成备份。

## 18. 设计决策与待详细设计确认项

### 18.1 已确认决策

1. 使用数字菜单作为 `frps`/`frpc` 默认交互方式；
2. 端口映射归入“修改当前 frps（服务端别名）端口映射”子菜单；
3. 每个 frps profile 的映射完全独立；
4. 服务端名称支持中文、字母、数字、`-`、`_`，不允许空格；
5. 服务端名称唯一且可修改；
6. 服务端通过编号选择；
7. Dashboard/API 管理端口由用户输入，默认端口为 7500；
8. 运行中的 profile 切换需要确认、自动重启并等待连接结果；
9. 连接检测最多等待 30 秒；
10. 删除 profile 时同时删除该 profile 的映射，不要求额外自动备份；
11. 首期采用单 frpc 实例切换多个 profile；
12. Linux 使用 systemd/OpenRC，Windows 使用 Windows Service。

### 18.2 详细设计阶段需要固定

1. 验证已确定的 frp v0.72.0 具体配置、命令和 Dashboard/API 行为；
2. GitHub Releases 的具体下载接口和校验文件格式；
3. 最终项目安装地址和镜像地址；
4. 最终 frp 版本对应的 Dashboard/API 接口；
5. frp TOML 字段与认证字段的版本适配方式；
6. Shell 和 PowerShell 的具体文件组织；
7. profile、mapping、state 的最终 TOML/JSON 文件格式；
8. 服务单元模板和 Windows Service 注册实现；
9. 文件日志采用保留 30 天、最多 500MB 的轮转策略，详细设计固定具体轮转实现；
10. HTTP/HTTPS 高级映射字段暂不进入首期菜单，仅保留扩展模型；
11. 防火墙只检测并提示，不由安装器自动修改 ufw、firewalld 或 Windows 防火墙；
12. 正式项目名称确定为 `frp-simple-bash`；命令继续使用 `frps`/`frpc`；Linux 配置目录确定为 `/etc/frp/`。Windows 对应配置目录在详细设计中按 `C:\ProgramData\frp-simple-bash\` 规划。

### 18.3 已补充确认的设计决策

1. 首期固定一个经过调研确认的稳定版，后续通过 `upgrade` 主动升级，不在每次安装时无提示追踪最新版本；
2. 首期必须实现 Dashboard/API 适配，不能仅依赖日志作为正式客户端连接信息来源；
3. 管理器数据采用 TOML + JSON：TOML 保存 profile 和映射配置，JSON 保存状态和索引；
4. 日志以系统日志为主，并提供文件日志轮转；
5. 防火墙仅检测并提示，不自动修改系统规则；
6. HTTP/HTTPS 首期只提供基础字段，高级字段暂时预留。

## 19. 概要设计结论

本系统采用“统一业务规则 + 平台适配层 + profile 隔离配置”的架构：

- Bash 和 PowerShell 负责跨平台安装与系统集成；
- `frps`、`frpc` 负责对应角色的数字菜单和管理操作；
- profile 管理多个 frps 服务端；
- active profile 决定当前 frpc 连接对象；
- 每个 profile 独立保存端口映射；
- 端口映射通过当前 frps 专用子菜单进行管理；
- 配置管理组件负责校验、原子写入和权限保护；
- 服务适配层负责 systemd、OpenRC 和 Windows Service；
- 连接检测负责切换后的 30 秒连接确认；
- Dashboard/API 组件负责服务端客户端连接信息展示。

该概要设计可以作为下一阶段详细设计和模块拆分的基础，但在正式编码前仍需要完成 frp 版本、API 字段和具体文件格式的技术确认。
