# 终端交互改进调研与方案

本文基于对 `lib/manager.py` 当前实现的逐行调研，记录交互问题、改进方案与取舍，作为后续实现依据。

## 一、调研发现的 6 个具体问题

### 1. 屏幕被清空，历史结果无法回看

`main_menu`、`mapping_menu`、`edit_profile`、`frps_config_menu`、`logs_menu` 每轮循环都调用 `clear_screen()`。用户执行「查看日志」「连接诊断」「客户端连接信息」后，一按回车菜单就把输出清掉，无法向上翻看。

实测证据：`clear_screen` 定义在 `lib/manager.py:383`，被 6 处菜单循环调用。

### 2. 清屏与重绘顺序导致状态闪烁

`main_menu` 先 `clear_screen()`，再 `show_status()`，再 `choose()`。每次返回上级都整屏重绘，长菜单在 SSH 小窗口里会滚动跳动。

### 3. 结果与菜单混在同一个流

`result_ok/result_info/result_error` 只是 `print`，没有视觉边界，也没有「本次操作 → 结果」的归属关系。用户连续操作时无法区分哪条结果属于哪次输入。

### 4. 返回语义不统一

- 主菜单：`0. 返回上一级`，实际是退出程序；
- 子菜单：`0` 返回上级；
- 表单输入：没有取消键，只能 Ctrl+C；
- 端口映射子菜单：`0` 返回，但选择映射时 `0` 是「取消选择」还是「返回」含义不清。

### 5. 输入提示不一致

`choose()` 用「请输入编号 > 」，`ask()` 用「字段名：」，日志/配置/备份菜单手写 `ask('请输入编号 > ')`，三套风格混用。字段输入也没有示例格式。

### 6. 确认与取消缺少默认值和后果说明

`confirm()` 只显示 `[y/N]`，删除类操作没有列出将被删除的具体对象和数量；升级/卸载没有展示影响范围。

## 二、改进方案

### 2.1 保留历史输出，不清屏

- 移除菜单循环里的 `clear_screen()`；
- 改为「分隔线 + 标题」分段渲染；
- 新增 `--clear` 或环境变量 `FRP_UI_CLEAR=1` 时仍可整屏刷新，默认不清屏。

理由：宝塔 `bt` 同样是追加式输出，用户能向上翻看历史；日志类命令必须保留输出。

### 2.2 统一区块样式

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 frps 服务端管理
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 状态   运行中
 版本   0.72.0
 监听   0.0.0.0:7000
 Dashboard  http://127.0.0.1:7500
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
 1) 查看服务信息
 2) 启动 frps
 ...
 0) 退出
```

- 状态区用两列对齐，字段名固定宽度；
- 菜单用 `1)` 而不是 `1.`，与状态区的点号区分；
- 分区之间用同一条横线，避免多种分隔符。

### 2.3 结果块带标题与归属

```
[成功] 启动 frps
       当前状态：运行中
```

```
[失败] 启动 frps
       原因：服务启动失败
       建议：查看日志（主菜单 7）
```

- 第一行是标签和动作名；
- 第二行起是细节，缩进对齐；
- 失败时统一带「建议」行。

### 2.4 统一返回与取消语义

- 任何菜单 `0` = 返回上一级；主菜单 `0` = 退出；
- 任何输入 `q` = 放弃当前操作并返回上级；
- 确认提示 `[y/N]`，默认 N；危险操作要求输入 `YES`；
- 列表选择时 `0` = 取消选择并回到当前菜单，不退出菜单。

### 2.5 统一提示与输入格式

- 选择：`请选择 [0-9] > `
- 文本：`服务端名称（例：生产服务器）：`
- 密码/token：隐藏输入，提示「输入不回显」；
- 非法输入：`[失败] 无效编号，请输入 0-9 之间的数字。` 并重新提示。

### 2.6 状态栏常驻关键信息

每次渲染菜单前显示一行紧凑状态：

```
frps | 运行中 | 0.72.0 | 0.0.0.0:7000 | Dashboard 127.0.0.1:7500
```

frpc：

```
frpc | 运行中 | 生产服务器（192.0.2.10:7000）| 已连接 | 3 个映射
```

## 三、实现范围（先加深，不扩展新功能）

只改交互层与已有功能的行为，不新增功能模块：

1. 交互基础函数重写：`clear_screen`、`pause`、`result_*`、`choose`、`ask`、`confirm`；
2. 主菜单与 5 个子菜单统一渲染；
3. 结果块统一格式；
4. 状态栏与状态区对齐；
5. 返回/取消语义统一；
6. 更新测试断言与文档。

## 四、取舍

- **不清屏的代价**：长时间会话输出变长。缓解方式是状态栏紧凑、结果块简短，并提供 `FRP_UI_CLEAR=1` 可选清屏。
- **不用 curses/rich**：保持零依赖，兼容 Debian 最小安装和 Windows PowerShell 管道调用。
- **`q` 与 `0` 并存**：`0` 保持文档兼容，`q` 作为快捷取消。

## 五、验收标准

- 执行「查看日志」「诊断」后向上翻页仍能看到输出；
- 每个菜单都能用 `0` 返回上一级，主菜单 `0` 退出；
- 表单输入 `q` 可放弃并返回，不写入配置；
- 所有失败提示包含原因和建议；
- 测试覆盖返回、取消、非法输入、结果标签。

## 六、实现结果

已按方案落地：

1. 默认不清屏，改为区块渲染，保留历史输出；`FRP_UI_CLEAR=1` 可恢复清屏；
2. 统一 `━━━` 区块标题、`1)` 菜单编号、`0)` 返回；
3. 结果块带 `[成功]/[提示]/[失败]` 标签，失败附建议；
4. 状态面板两列对齐，菜单上方常驻一行紧凑状态栏；
5. `q` 取消当前操作，`0` 返回上级，主菜单 `0` 退出；
6. 危险操作要求输入 `YES`。

验证：57 项测试通过，实际渲染已确认区块、状态栏与返回提示正常。
