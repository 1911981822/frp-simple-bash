# 国内下载站部署与维护

## 1. 当前方案

使用现有宝塔 Nginx 提供只读静态文件，域名为 `download.sueiyuan.top`。安装器优先访问此下载站，传输失败后回退 GitHub 官方地址。

首期管理器发布版本为 `v0.1.0-mirror.1`，原生 frp 固定 `v0.72.0`，WinSW 固定 `v2.12.0`。

本站只提供安装脚本、源码包和上游发布包，不提供管理 API、上传接口、PHP 程序或数据库服务。

## 2. 服务器布局

```text
/www/wwwroot/download.sueiyuan.top/
├── index.html
├── .well-known/acme-challenge/       # 证书 HTTP 验证目录
├── frp-simple-bash/
│   ├── install-frps.sh
│   ├── install-frpc.sh
│   ├── install-frps.ps1
│   ├── install-frpc.ps1
│   ├── install-windows.ps1
│   └── releases/
│       └── v0.1.0-mirror.1/
│           ├── source.tar.gz
│           ├── SHA256SUMS.txt
│           ├── lib/…
│           ├── bin/…
│           └── 其他源码文件
├── frp/
│   └── v0.72.0/
│       ├── frp_0.72.0_linux_amd64.tar.gz
│       ├── frp_0.72.0_linux_arm64.tar.gz
│       ├── frp_0.72.0_windows_amd64.zip
│       └── frp_sha256_checksums.txt
└── winsw/
    └── v2.12.0/
        ├── WinSW-x64.exe
        └── SHA256SUMS.txt
```

网站配置位于 `/www/server/panel/vhost/nginx/download.sueiyuan.top.conf`，证书位于 `/www/server/panel/vhost/cert/download.sueiyuan.top/`。站点已登记宝塔站点数据库，便于在面板中查看；保持纯静态，不要为此站开启 PHP。

Nginx 限制为 GET/HEAD，关闭目录列表，拒绝隐藏文件、私钥及临时上传文件。源站 HTTPS 支持 Range 下载；使用 `X-Content-Type-Options: nosniff` 防止内容嗅探。

## 3. HTTPS 与 Cloudflare

2026-11-09 通过宝塔 ACME HTTP 验证申请证书，证书 SAN 为 `download.sueiyuan.top`，到期日为 2027-02-07。证书订单已保存，宝塔现有自动续签任务启用。远期实际续签仍需要监控，不能将一次签发成功视为将来一定续签成功。

部署时观察到域名经 Cloudflare 代理，公网解析返回 Cloudflare IP，而不是用户源站 IP。需要区分：

- **源站在国内**：文件存储在用户授权的国内服务器上。
- **国内直连下载**：域名必须解析到源站，或使用真正的国内 CDN；Cloudflare 全球代理不保证国内访问速度。

建议在 Cloudflare 将该下载域名切换为 **DNS only（仅 DNS，灰云）**，检查 A 记录指向源站，移除不匹配的 AAAA 记录。保留其他业务域名设置。

若继续使用 Cloudflare，应设置 SSL/TLS 模式为 **Full (strict)**。Flexible 模式的回源 HTTP 会导致普通 HTTP→HTTPS 跳转循环；站点目前兼容代理传递的 `X-Forwarded-Proto`，但兼容配置不能替代 Full (strict) 对回源链路的加密。

部署验证期间，Cloudflare 曾缓存某个原生包 URL 的旧 301。安装器在镜像资源 URL 附加固定发布版本查询参数，避免复用旧重定向缓存；原始文件与校验值不变。更改代理或站点跳转后也可在 Cloudflare 清理相关 URL 缓存。

## 4. 下载顺序与校验规则

### Linux

1. 单文件入口下载固定管理器源码包及 `SHA256SUMS.txt`。
2. 检查源码包摘要，解压后运行共用安装器。
3. 共用安装器优先使用国内原生 frp 包，再回退官方 Release，最后尝试官方资产 API。
4. 无论下载来源，检查内置固定原生 SHA256。
5. 若设置 `FRP_ARCHIVE_PATH`，改用该本地包，但仍执行摘要校验。

### Windows

1. PowerShell 入口优先下载国内共用安装器，失败回退 GitHub Raw。
2. 安装所需单个脚本从固定管理器版本目录获取，缺失时回退 GitHub Raw。
3. 原生 frp 与 WinSW 优先访问国内镜像，再回退官方资源。
4. 采用固定摘要检查，不为了镜像成功路径而强制请求 GitHub metadata。

所有下载保留正常 HTTPS 证书校验，禁止 HTTP 降级。**传输成功但校验不通过时立即停止，不自动切换来源掩盖异常。** 只有网络/HTTP 下载失败才选择备用源。

管理器源码包的同源摘要用于检查传输完整性，不是独立签名；Windows 单文件源码下载依赖 HTTPS 信任。若需要防止镜像站自身被篡改，后续应引入独立签名和公钥验证。

## 6. 构建管理器源码包

使用[源码打包工具](<../tools/build_release.py>)：

```bash
python3 tools/build_release.py --version v0.1.0-mirror.1
```

输出：

```text
dist/v0.1.0-mirror.1/source.tar.gz
dist/v0.1.0-mirror.1/SHA256SUMS.txt
```

源码包顶层固定为 `frp-simple-bash/`。打包时纳入 Git 已跟踪及非忽略新增文件，排除下载包、本地配置、缓存和 dist 目录。工具固定归档时间等元数据，拒绝无意覆盖已生成的版本包。

发布步骤：

1. 完成代码测试与密钥检查，选择新的管理器版本号。
2. 同步更新入口和下载 helper 的版本号，避免入口与源码目录不一致。
3. 构建源码包，核对摘要并检查包内文件列表。
4. 上传到网站新版本目录，先使用临时文件名。
5. 服务器验证源码包和全部原生包的固定摘要。
6. 校验成功后原子发布正式文件名；解压源码中的相对路径，供 Windows 单文件下载使用。
7. 最后更新顶层安装入口，使用户进入已发布的新版本。
8. 用源站 HTTPS 和公网域名分别检查完整下载、摘要、安装和回退行为。
9. 提交并推送对应源码，保留原生旧包和旧管理器版本。

固定版本目录发布后不要覆盖；有修改时使用新版本目录。清理旧版本前确认没有安装器继续引用。

## 7. 下载源配置

```bash
# 禁用国内源，使用官方地址
sudo env FRP_MIRROR_URL=off bash install-frps.sh

# 自建另一个 HTTPS 镜像（目录布局相同）
sudo env FRP_MIRROR_URL=https://mirror.example.com bash install-frps.sh

# 使用已校验的本地安装包
sudo env FRP_ARCHIVE_PATH=/absolute/path/frp_0.72.0_linux_amd64.tar.gz bash install-frps.sh
```

`FRP_MIRROR_URL` 显式设为空或 `off` 表示禁用；未设置时使用默认站点。管理员用 sudo 执行时，应明确通过 `env` 传递需要的环境变量。

## 8. 运维检查

- 宝塔中保持该站点纯静态，定期检查证书有效期和续签日志。
- 检查磁盘容量、带宽、访问量及 Nginx 日志轮转。
- 下载站目录只放公开发布内容，不放配置备份、token、账号、证书私钥或项目 Git 元数据。
- 同步程序仅在完整下载并通过 SHA256 后发布正式文件；不暴露 `.partial`。
- Nginx 修改先执行配置检查，通过后平滑重载，不重启其他业务进程。
- 保留首次部署前的宝塔站点数据库备份与下载站配置备份；不要为了回滚新站覆盖整个站点数据库，避免破坏其他站点后续修改。

测试范围：下载 helper 的自动化模拟测试、真实 HTTPS 源站与公网下载检查、Debian 安装回归。Windows SCM 和 PowerShell 实机仍需独立验收。
